## <Body section — name to suit the content>

The actual content. Memos are flexible — pick the structure that serves the topic. Common shapes:

### Investigation memo
- **Symptom** — what was observed.
- **Reproduction** — minimal steps.
- **Root cause** — what was actually broken.
- **Fix** — what was changed (link to PR / commit).
- **Prevention** — guard rails (tests, lints, CI checks) added to keep it from coming back.

### Playbook memo
- **When to use this** — triggering conditions.
- **Steps** — numbered, copy-pasteable commands.
- **Verification** — how to know it worked.
- **Rollback** — how to undo it.

### Compatibility / Reference memo
- **Background** — what the constraint is.
- **What works** — current known-good combination.
- **What doesn't** — known-bad combinations.
- **Workarounds tried** — historical record so we don't repeat them.

### Post-mortem memo
- **Timeline** — UTC, terse.
- **Impact** — who was affected, for how long.
- **Root cause** — technical and process.
- **Action items** — owner + due date for each.
